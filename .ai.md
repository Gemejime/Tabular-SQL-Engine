## Non-Negotiable Invariants

1. **Continuous Doc API & OpenAPI Maintenance**: The [`.ai/doc-api.md`](.ai/doc-api.md) file and OpenAPI 3.1 specification (`api/openapi/openapi.yaml`) MUST be kept updated on **every code change or addition**, regardless of how small the modification is, if need be.
2. **Secured Logging**: All logging must be structured JSON. Strictly redact authorization headers, bearer tokens, AWS credentials, presigned S3 query parameters (`X-Amz-Signature`, `X-Amz-Credential`, `X-Amz-Security-Token`), and sensitive tenant PII/PHI or raw SQL literal values before emission.
3. **Process-Isolated Disposable Sandboxing**: Execute every DuckDB query inside an isolated ephemeral child subprocess (`pebble.ProcessPool` / `multiprocessing` supervisor with `max_tasks=100`) running an ephemeral in-memory database (`duckdb.connect(":memory:")`), so native C++ faults or isolated `SIGKILL` cancellations never crash the primary Arrow Flight daemon or sibling workers.
4. **Deterministic SQL AST Whitelisting**: Enforce pre-execution AST validation via `sqlglot` (within $\le 2\text{ ms}$) permitting only read-only `Select`, `With` (CTEs), and `Union` constructs and pre-approved function namespaces, blocking DML, DDL, `PRAGMA`, `SET`, `COPY ... TO`, `ATTACH`, `LOAD`/`INSTALL`, `SUMMARIZE`/`DESCRIBE`/`SHOW`, and DuckDB filesystem functions (`read_csv`, `read_parquet`, `scan_parquet`, `write_csv`).
5. **Hard DuckDB Sandbox & Memory Ceilings**: Targeting DuckDB `>= 1.2.0` (which supports `allowed_paths`), configure `SET allowed_paths = ['<validated_parquet_path>']` for only the single validated `{hash}.parquet` cache file before binding the view and locking every DuckDB instance with `enable_external_access=false`, `lock_configuration=true`, `temp_directory=''`, `threads=2`, and aggregate `memory_limit <= 2.5GB` across `POOL_SIZE` workers inside a `6.0 GiB` container cgroup (`4.0 GiB` request, `>= 2.0 GiB` daemon/Arrow headroom, `1.5 GiB` OS page cache margin), with `jemalloc` preloaded globally (`LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libjemalloc.so`).
6. **Subprocess Circuit Breaking**: Enforce a hard `5s` query execution deadline via cancellation monitors that `SIGKILL` and respawn only the offending child worker process.
7. **Tiered Ingestion & Chunked Flight Egress**: Serve cached `{hash}.parquet` artifacts from disk-backed `10 GiB` NVMe `emptyDir` storage (with single-flight coalescing, in-memory LRU eviction, and lock-free concurrent readers; never `10 GiB` `tmpfs` in a `6.0 GiB` pod), hydrate cache misses via S3 range reads without monolithic Python heap buffering, and stream `RecordBatchReader` chunks over Apache Arrow Flight IPC (`DoGet`) directly to `rag-search-orchestrator`.
8. **Code Cleanliness & Quality Gates**: All Python code must pass `ruff check .`, `ruff format --check .`, `mypy`, `bandit`, `pip-audit`, and `pytest` across unit, security, integration, and chaos suites.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Ruff formatting and linting: `ruff format --check .` and `ruff check .`.
2. Run static type checking: `mypy cmd internal api`.
3. Run security & dependency audits: `bandit -r cmd internal api -ll` and `pip-audit`.
4. Run test suites: `pytest -v test/`.
5. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and `api/openapi/openapi.yaml` are updated with all API, Flight schema, metric, or configuration modifications.
6. Verify Secured Logging rules: Ensure no AWS credentials, presigned query strings, bearer tokens, or PII are logged.
7. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
